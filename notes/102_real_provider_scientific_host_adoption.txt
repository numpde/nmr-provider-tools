# Can the four real providers do their jobs through the new SDK?

2026-11-20. Source investigation, adoption decisions and critical review.

## Goal and feasibility

Yes. The inspected scientific entry points fit the SDK's Contribution, Analysis,
operation, state and result ownership model. Each provider can accept its supported
inputs, perform the intended calculation and deliver its result through that model.
The work is concrete provider adaptation, installed integration and the bounded
SDK/deployment decisions below. Real-model execution through the proposed adapters
still needs demonstration.

| Provider | Job the adapted provider must do |
| --- | --- |
| NMRPeak HF | Interpret or directly admit formula/proton input and generate ordered molecular candidates with the selected HF model. |
| NMRPeak CHF | Perform the corresponding calculation with formula, proton and carbon input and its own CHF model. |
| SECS | Select and verify dense proton spectrum data and formula evidence, prepare the spectrum, then retrieve/search candidates using the selected model and index. |
| NMRNet | Obtain supplied or generated molecular coordinates and return correctly associated per-atom H/C predictions for the requested geometries. |
| Magnet E01/E02 | Admit the respective NMR inputs and generate candidates with the selected models, generation settings and seed. |
| Magnet G01 | Predict forward NMR properties for the admitted molecular graph and solvent, retaining atom correspondence and meaningful output arrays. |

Existing code is evidence of present behavior. It can contain defects or unnecessary
restrictions. Retain justified scientific meanings, accepted public obligations
and truthful ownership. Internal protocols, accidental exit behavior, repeated
loading, warning suppression and private exception classes can change. Investigate
baseline discrepancies against the intended calculation and public contract before
deciding which implementation is correct.

Use portable SDK call bindings and select the host at startup. Process execution
is the recommended first deployed profile for native/GPU workloads. The same
workflow can use threads in a compatible profile. Advertising threads requires
appropriate dependencies, grants, global-state handling and stopping behavior.
A blocked thread cannot be forcibly retired independently of its enclosing process.

## Common adaptation

Each provider keeps a small AnalysisSession service adapter. It binds an acknowledged
Attempt to its input, checks current permission, calls science, builds the public
result and settles its resources. Existing SDK controller/delivery owners handle the
surrounding service obligations.

A Contribution owns its scientific implementation and operations. Use SDK Analysis
for actual request-local scientific state, and produced state with CONSUME/BORROW
according to how science uses it. Installed factories construct lightweight objects.
Initialization acquires resources under SDK ownership and retains partial acquisitions.

SDK submissions, observations and reference checks replace private scientific framing
and mirrored operation state. SDK cleanup and native runner retirement replace duplicated
lifetime machinery. Contributions call numerical implementations directly. Wrapping
an old scientific worker client inside a contribution would retain two execution owners.

Keep the mapping between Attempt, allocation, analysis, operation and verified assets
in the adapter. Check permission immediately before submission after awaits. Retain
the original Submission before sending and use the original deadline. Cancellation
ends a wait without erasing admitted work. A new invocation means a new calculation.

Transfer exact result bytes/evidence into service ownership before releasing their
scientific result. Service retains the report through delivery. A child reference
cannot preserve bytes after death. Public ResultConsumption supports a retained
read/receiver handoff followed by release.

| Observed fact | Target treatment |
| --- | --- |
| Scientifically unsuitable input with a reviewed reason | Input rejection, with interpreter correction where appropriate. |
| Correlated scientific operation definitively failed | Retain operation/stage facts and use a reviewed provider failure mapping, with safe wording and independent resource settlement. |
| Computation completed but encoding/report assembly failed | Retain known completion and available data. Repair reporting where possible. Reporting failure grants no scientific replay. |
| Operational failure lacks a reviewed public mapping | Preserve the evidence and keep public disposition unresolved. Distinguish that from unknown scientific execution. |
| Reply lost and completion cannot be established | Retain execution uncertainty and original ownership. No fabricated outcome or automatic replay. |
| Native exit observed before deliberate interruption | Use original-exit evidence and the controller's Attempt/phase checks if publishing a crash outcome. |
| Deliberate stopping or exit observed only afterward | Retain interruption/retirement facts without reconstructing an original crash. |

An ordinary fault need not be turned into a process crash. It also does not prove
safe model reuse. The scientific owner decides reuse from actual mutation/device
behavior. Withdraw uncertain or poisoned allocations before new admission and retain
their cleanup evidence.

The initial adaptation should use no automatic scientific retry unless a provider
has a demonstrated availability requirement. Migrate existing retry configuration
explicitly, including rejecting unsupported nonzero settings. Any retained retry
needs a reviewed known failure, fixed scientific inputs, original-owner settlement
and renewed permission for a fresh execution. Transport deduplication and
re-observation continue to address the original operation.

hosting.py::ResultConsumption, process_host.py and process_wire.py. Declaration

## NMRPeak HF and CHF

Use a separate contribution/allocation for each model, common family science and
distinct input declarations. Prepare model tokens, retain them as consumed state,
and generate from those admitted tokens. This gives preparation a concrete product
and removes repeated tokenization. Verify deterministic tokenization for the admitted
input/assets and dispose abandoned tokens. Keep structured and interpreter-assisted
prose routes for both families.

Retain HF/CHF scientific materialization, verified checkpoint/dictionary loading,
decode choices, candidate ordering and meaningful provenance. Add explicit partial
initialization/close ownership. Remove private VALIDATE/GENERATE framing and mirrored
parent/child preparation bookkeeping as SDK state takes custody.

Change ordinary exception handling. The current family worker sends FailedFrame
and rethrows, allowing the parent to classify the ensuing native exit as a crash.
The SDK retains a calculation failure while the worker remains alive. The target
uses a correlated scientific-fault outcome and a reviewed safe public mapping.
NMRPeak's current policy covers source issues, loaded-input rejection and interpreter
unavailability, so add scientific-fault publication rules in the adapter. Empty
tokenization and dictionary mismatch belong to the operational path. Over-limit
input can be corrected.

Keep actual native death distinct. Use original-exit evidence when available and
retain uncertainty otherwise. Retirement follows resource health and cleanup needs
independently of public classification. Reproducing exception-to-crash behavior
would add no scientific value.

At the inspected baseline a lane error could stop both offerings. The adoption
requirement is to withdraw the failed lane and keep the healthy sibling serving.
API, identity and shutdown failures retain their proper scope.

The SDK host must expose confirmed exit of the original worker even when its
allocation is idle. Observation must preserve the worker's retirement allowance
through healthy idle time and retain the original lifecycle evidence for cleanup.
On confirmed unexpected exit of a serving worker, NMRPeak maps the allocation to
HF or CHF, stops admitting work for that offering and updates the list supplied
to SDK Hello publication. Any active Attempt retains its own outcome and evidence.
Under the qualified local API response budget, measure withdrawal from worker exit
through acknowledgement of the corrected Hello. Local readiness reflects whether
any offering can serve.

## SECS

Use one contribution holding the model and FAISS index, with inspect, prepare and
execute. A per-analysis InputAdapter owns representation discovery and claims.
Its token key, Attempt scope and claim registry represent selection state before
a prepared spectrum exists. Repeated inspection/preparation shares that owner.
Analysis close disposes claims. Replacement requires fresh inspection before a
selection is usable. The existing opaque claims may later simplify to SDK-owned
references if they retain source correlation and changed-source rejection.

Preparation returns an immutable materialized spectrum and canonical formula as
consumed state. Execution creates a per-execution GraphGA optimizer from frozen
worker settings and seed. Keep one configuration authority. Variable per-request
settings would be a separate product choice. Model/index acquisitions require
separate retained owners for partial initialization and cleanup.

Keep source acquisition and membership reconciliation in the service. Send verified
receipt/path metadata and check identity, digest and size before reading. Current
limits of 128 MiB/upload and 256 MiB aggregate already use a file boundary. Delete
files only after original readers settle. Successfully materialized spectrum state
is independent of those files. Remove integer preparation counters, string-command
dispatch and duplicated channel/native ownership.

## NMRNet

Use contributions for source reading, conformer generation and prediction with their
actual environments/grants. Keep source selection, interpretation and ResultPlan
in the service. Service preparation currently acquires prediction, reserves report/
evidence capacity and retains ordered inputs. Service execution performs scientific
batch preparation and prediction. Declare the scientific calls explicitly and keep
phase/effect facts truthful if their scheduling changes.

Prediction uses a fresh scientific Analysis and consumed state for a complete
admitted batch. The contribution initially owns loader configuration/resources.
Per-geometry/head model/scaler loading is a conservative memory baseline under the
current 4 GiB grant. It is a resource choice open to measured improvement. Persistent
allocations can serve fresh analyses without implying both heads remain cached.

The NMRNet deployment owner must change lifetime configuration for persistent
roles. deployment.py currently renders --operation-seconds from a one-request
budget; that native deadline starts at child launch. Use --owner-session-lifetime
for a persistent host while retaining bounded request, startup and retirement
policies. If a maximum allocation age is desired, withdraw it deliberately before
expiry. Qualify a later request beyond the old child cap, or demonstrate planned
withdrawal with truthful settlement. Two quick requests cannot prove this boundary.

A literal persistent port exposes a diagnostic defect. Scaler warnings currently
follow Python's process-global suppression, while new loader objects reset only
their captured list. Report relevant verified asset compatibility facts for every
calculation using those assets, independently of repeated Python emission. Keep
incidental warnings as separate scoped operator evidence. Qualify consecutive use
and warnings-as-errors behavior before reuse. The scientific owner also resolves
global warning/native logging capture for thread coexistence.

## Implementation and completion

Start with an exact installed SDK candidate. Port one real service route together
with its contribution and result/failure mapping. HF is a small first slice because
current CPU payloads are well below the SDK ceiling. Complete CHF and real service
independence in the same provider milestone. Then adapt SECS, NMRNet's full workflow
and all three Magnet models. This is a suggested order, with the full inventory
remaining the completion target.

Use deterministic science through real adapters first to prove permission,
correlation, outcomes, handoffs and cleanup. Then run pinned actual models/input
routes against reference calculations with explicit numerical tolerances. Existing
scientific/reproduction tests supply evidence. Investigate disagreements, including
possible defects in today's provider. Adapt behavioral tests and remove obsolete
mechanism assertions.

Record tested source revision, wheel/image identity, model/configuration identity,
profile, command, counts, failures and skips. Installed SDK lanes use
DOCKER_CONTEXT=science and WHEELHOUSE=/home/ra/Downloads/wheelhouse, with
PRIVACY_TESTS=0 for the existing campaign. Focused disclosure checks required by a
port still need evidence before its profile is claimed. Repository checks remain
deferred with separate merge/release disposition.

A provider is adapted when its real entry point performs every declared supported
job, returns intended scientific information, handles known/unknown effects honestly
and settles owned resources. Migrated paths contain one scientific execution
authority. Adding an ordinary model changes provider science, declarations,
construction and configuration, without a new execution state machine. Witness
device release and responsiveness for advertised profiles, and exercise sibling
availability through the real service.
