Provider-deploy: extract the operation, not a deployment framework
================================================================

Revised 2026-11-01 after implementing adapters for NMRPeak and NMRNet.
The original proposal was too broad and its interface did not fit either caller.
This revision replaces that proposal; it is not a release-readiness claim.

Goal
----

A new provider should supply its deployment policy, not copy host identity
probing, Linux map validation, process supervision and probe cleanup. The first
shared operation measures a selected container namespace's host UID/GID maps.
It returns them only after its exact owned probe has retired.

The test of this boundary is two small real caller adapters. Package features
and internal abstractions are not accomplishments by themselves.

What the callers taught us
-------------------------

NMRPeak (numpde/nmrpeak-repro, ec205295) already selects a local Unix endpoint,
uses host Python 3.11+, and probes its image with /usr/local/bin/python3.12 as
65532:65532. It translates UID 65532 and the installing user's UID before
applying its own ACL and projection-helper policy.

NMRNet (numpde/nmrnet-repro, e119063b) passes a previously selected immutable
endpoint to its shell deployment launcher. Its image exposes
/opt/provider/environment/bin/python. It needs forward UID/GID mappings for
container root and the installing user, then chooses its own helper identity.
Its separate provisioning path still uses inverse mapping and is not migrated
by this extraction.

Consequences:
* Do not resolve a Docker context again. That could measure a different engine
  from the one the provider subsequently uses.
* Accept the image's Python interpreter path, not an invented /bin/sh dependency.
* Return validated maps to Python. Translate requested IDs inside the CLI for
  shell callers; do not make shell callers parse kernel mapping rows.
* Keep host Python 3.11 compatibility. Declare NMRNet's new host prerequisite.
* Keep ACLs, helper selection, image preparation and deployment sequencing local.

Small public contract
---------------------

The request names the pinned Unix endpoint, an approved local image, its Python
interpreter and numeric probe user. Namespace mode and bounded timing have
usable defaults. Image acquisition is never implicit. The provider may select
its Docker executable explicitly; it cannot supply arbitrary probe code.

The result contains validated UID and GID maps. A failed operation carries no
usable maps. It describes the failing stage and safe reason, secondary cleanup
problems, and the known resource identity for operator investigation. Observation
validity and resource retirement are separate facts.

Internally, one immutable probe specification defines both creation and
ownership verification. One concrete owner performs create, observe and retire.
Linux evidence checks and bounded Docker transport remain separate modules.
There is no backend registry, workflow language, task queue or recovery service.

Success and uncertainty
-----------------------

Run on the local Linux host with initial user/PID namespace evidence and genuine
host /proc visibility. Bind map observations to the exact container, random
token, host PID and process start identity. Reject incomplete or changing facts.
Only exact verified owned resources may be removed. Cancellation still enters
bounded cleanup; a lost mutation reply never authorizes a second creation.

A successful return requires fresh valid maps and confirmed container/process
retirement. A failed cleanup cannot be presented as successful measurement.
Proving that an owned container may be removed is distinct from proving its
mapping observation valid; observation failure must not prevent safe cleanup.

Crash replay is deliberately outside this operation. Neither original caller
required it. A prototype journal/recovery subsystem added state, schemas,
locking and caller file-management obligations without advancing extraction.
It was removed rather than generalized. Failure diagnostics are not a durable
transaction log. Abrupt death can lose those diagnostics. The finite Python
lifetime and Docker auto-removal limit a started probe; a crash between create
and start can leave a stopped container requiring manual investigation. Do not
promise automatic cleanup after SIGKILL, host loss or an unreachable engine.

Qualification
-------------

Exercise actual Python and shell adapter boundaries, not invented example APIs.
Test lost replies independently from engine-side effects, subprocess cancellation,
map/process changes, exact ownership, cleanup failures and diagnostic separation.
Use real subprocesses and /proc where available, while naming simulated Docker
and substituted host/socket checks explicitly.

Rootful/rootless engines, both actual image interpreters, non-root host callers,
and each provider's maintained container test lane must pass before adoption.
The shared probe standardizes finite resource caps; verify them with both images
rather than assuming identical interpreter startup behavior. Local candidate
adapters and fake-engine tests are not production migration or qualification.
