## Supported v1 and next boundary

The supported v1 profile is thread or persistent process execution of the
existing declared Contribution operations through portable bindings. Process
construction uses an installed factory and explicit bounded startup data. Each
process host owns one allocation and one active analysis; prepared state stays
worker-owned and reference-addressed. Communication uses the bounded private
protocol and pinned installed Linux/container code. Unknown replies retain the
original operation; no automatic replay is granted. Shutdown retains original
scientific cleanup followed by native retirement.

The documented two-second synchronous control allowance, 1 MiB encoded input/
result limit and 8 MiB frame limit remain explicit constraints. This is an
execution boundary within existing containment, not another security sandbox.

Independent offerings, real-model/GPU execution, controlled replacement,
unattended parent-death containment, broader concurrency, cross-version workers,
additional platforms and automatic recovery remain outside this qualification.
Next, demonstrate two independent offering lifetimes without multiplying shared
capacity, then adopt one real scientific model. Repository checks must receive
their own disposition before any eventual merge-readiness claim.
