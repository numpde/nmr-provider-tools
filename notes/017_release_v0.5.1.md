# provider-core 0.5.1

This release fixes recovery from DNS failures, connection loss and TLS EOF in the shared signed API client. Recovery requires evidence from the original network operation, confirmed retirement and the existing operation-specific permission. Certificate verification failures, malformed protocol data, local callback failures, caller cancellation and independent cleanup failures do not gain retry permission.

Providers retain their existing recovery rules: fresh reads, current Hello and progress, the same START key and facts, unchanged terminal commands, and a still-needed read capability. Existing request, byte and time budgets remain in force. Active Attempt observation now respects Retry-After without extending its original observation gap; an observed native crash can still interrupt the wait.

`HttpTransport.exchange`, `exchange_file` and `exchange_decoded` accept an optional absolute event-loop deadline, `not_after`. It bounds the caller's observation of the request and all later cleanup of that original exchange; it cannot guarantee that underlying work ends by that time. Unfinished work remains owned, and expiry does not prove retirement. A response first observed after the cap is refused, even if it completed earlier. Omitting the cap retains the configured exchange and retirement allowances.

Transport failures retain the first caller cancellation separately from native I/O and cleanup evidence. Protected diagnostics expose those original facts. Deployment refusal types now have one canonical identity when invoked through their module CLIs, and consumer detail hooks can delegate to `describe_core_failure(error, text, diagnostic_window)`. Larger diagnostic rendering and sink-budget changes remain deferred; this release does not promise that every diagnostic record fits an atomic pipe write.

API and delivery consumers affected by availability failures should adopt this patch. NMRPeak's model HTTP integration also needs the absolute deadline. Python 3.12 and the 0.5.0 installation profiles remain unchanged: use `provider-core[api]` or the full issued lock for HTTP, API and delivery interfaces; the native-only lock remains dependency-free. Acquire the wheel and hash locks from the [GitHub release assets](https://github.com/numpde/nmr-provider-tools/releases/tag/v0.5.1) through the consumer repository's normal build path.

Qualification covers installed unit, native and integration behavior, the exact release artifacts and source rebuild. Consumer-image checks and deployment have their own evidence; publishing these files does not establish a production rollout. See the [package documentation](https://github.com/numpde/nmr-provider-tools/blob/v0.5.1/packages/provider-core/README.md) for integration contracts.
