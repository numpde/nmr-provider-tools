Deferred wheelhouse work
========================

The joint deployment is a milestone, not completion of the shared wheelhouse
migration. Complete qualification of the provider-core dependency-download
replacement and every provider's remaining runner and
worker migration. Qualify their normal cold paths before claiming completion.

All four provider repositories now pin shared tool 0.5.11 for future
acquisition and streaming. NMRNet checked its own cached source-and-wheel
stream on both hosts, but has not rebuilt all image roles with that new pin.
NMRPeak built its CUDA benchmark image offline without running GPU inference.
Its provider and CPU runner acquisition now also reuse a complete pool offline
on both hosts; the CUDA benchmark selection passed locally. An incomplete or
corrupt partial pool can still proceed to index metadata lookup.
SECS built its migrated GPU worker image offline; its deployed GPU worker is
still on the earlier image pending the separately scoped GPU qualification.
Healthy deployments have not been restarted merely to update tool pins.
The shared tool image's normal build bootstrapped the genuinely absent 0.5.12
streamer and streamed existing wheel inputs on both hosts. Version 0.5.12 also
corrects 0.5.11's local-version projection limitation.

The following items do not need to delay the current deployment:

- The provider-core repository's shared-publisher replacement needs a genuine
  missing-artifact cold-path qualification through its normal Make target.
- Shared delivery's generated lock has been checked offline with the released
  publisher and cached wheel. A normal preparation with a genuinely missing
  release wheel still needs qualification.
- A wheel downloaded and discarded by a lock compiler for metadata may be
  fetched again by acquisition when the index lacks a metadata sidecar.
- NMRNet's acquisition launcher selects a network route even when its pool is
  complete. Its offline check cannot yet safely authorize a network fallback
  after an interrupted container; the worker's retirement needs an owner.
- Cache-aware projection uses current index metadata and excludes yanked
  candidates when non-yanked candidates exist. It cannot reuse an artifact
  absent from that metadata, and may prefer a non-yanked download to a cached
  yanked wheel. Explicit source and hash choices remain authoritative.
- The broad repository quality lane reports existing source-inventory,
  generated-file and policy findings alongside the wheelhouse changes. Triage
  those separately rather than expanding the provider deployment.

Offline checks on both hosts found the current provider-core locks complete;
the delivery runtime wheels, pinned release wheel and tool were also present
with matching hashes. No cached artifact was removed to manufacture a cold run.

WLAN DNS failures during host-local acquisition remain an operational issue:
retain the failing diagnostic and use the configured interface and resolver.
Do not silently switch the download route to complete a deployment.
The ProArt WLAN proxy also returned 502 for a GitHub release asset. The explicitly
allowed system route obtained that asset; package downloads remain on WLAN.

The first ProArt 0.5.10 release qualification saw an integration test expect
a direct aggregate timeout but receive a wrapped read timeout. The preserved
attempt failed; a second full ProArt qualification and the local qualification
passed. The timeout distinction remains uninvestigated beyond source review.
