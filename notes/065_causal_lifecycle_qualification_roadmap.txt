Roadmap: causal lifecycle qualification
======================================
2026-11-08 | Proposed implementation checklist | SDK source 743a652

Purpose and status
------------------
Implement the contracts in 064_causal_lifecycle_qualification.txt using the
existing SDK and consumer test infrastructure. Notes 058, 060 and 061 retain
their historical evidence and service-extraction decisions. This note orders
future work; it does not relabel historical results as current qualification.

All implementation boxes below are unchecked. Writing these notes runs no
tests and authorizes no dependency update, release, deployment or cutover.
Campaign sizes and repetition counts are starting proposals, not measurements.
Keep immediate recovery qualification independent of the later service move.
Use note 064's identifiers in witnesses and receipts: safety S1-S8, isolation
I1-I2 and conditional liveness L1-L3. A milestone need not prove every property;
name which properties and external assumptions its evidence actually covers.

2. Make the consumer witnesses causal before broadening them
-----------------------------------------------------------
[ ] Extend existing provider scenario fixtures with the smallest necessary
    typed observations: Job/Attempt, lane, original operation/generation,
    event kind, terminal operation/body identity, and observed acknowledgement.
    Order events using explicit gates and correlated observations. A timestamp
    describes elapsed time; it does not prove which operation caused an event.
[ ] For outage recovery, observe two distinct original terminal failures and
    their required settlement before restoring the endpoint. Verify the later
    success belongs to another eligible Job. A retry of one failed request,
    one controller observed twice, or a successful in-flight old request is
    not the recovery witness. Reuse Magnet's current implementation of this.
[ ] Replace rendered-message classification only where the scenario needs it:
    capture parent-observed HTTP refusal and operation identity at the real
    boundary, rather than searching exception/log strings for an HTTP code.
    A peer returning bytes does not establish that the parent consumed them.
[ ] In Magnet's existing lane-isolation test, add a direct held-lane event and
    explicit successful shutdown assertions in the test body. Replace status
    file polling where that event provides the same evidence. Preserve the
    independent lane's progress and later affected-lane continuation checks.
[ ] Take the behavioral verdict before emergency teardown. Teardown releases
    fixture gates and joins owned tasks/processes, but cannot turn a held claim,
    missing handoff or shutdown failure into success. Preserve both failures.

Exit: no fixed delay establishes a required ordering; original failure,
independent progress, later recovery and shutdown have distinct observations.
Do not expand a common event journal beyond the consumers that require it.

3. Add one composed state machine in the SDK
-------------------------------------------
Depends on: inventory and the acceptance distinctions in note 064.

[ ] Build the first test against real AttemptClaims, AttemptController,
    Interpreter and SupervisedChatTransport ownership. Substitute controllable
    launch/IPC/exit observation, API responses, scientific effects and delivery
    acknowledgements. Do not substitute a fake controller or copy its state.
[ ] Give independently active interpreters their own transport owners. One
    SupervisedChatTransport owns one active exchange; sharing claims/capacity
    does not authorize invented concurrent use of that object. Share captured
    ProseService bindings only where the real composition shares them.
[ ] Use Hypothesis RuleBasedStateMachine, within the existing unittest runner.
    Keep one persistent asyncio.Runner/event loop per example. Synchronous
    rules drive that loop and retained tasks; do not use asyncio.run per rule.
[ ] Generate eligible commands and completion order: admit/refuse/lose START,
    finish or fail launch, release partial/full replies, expire permission,
    revoke, return preparation/scientific outcomes, acknowledge or reject
    handoff, observe original exit, cancel an observer and request stop.
    Preconditions enforce causality while permitting late/stale completions.
    Supply outcomes through the controlled external ports; the real SDK accepts
    preparation and selects terminal decisions. Never set controller state to
    manufacture a transition or make an unresolved outcome settle.
[ ] Establish note 064's deterministic trace before extending the generator:
    hold A's original retirement while independent B completes; then expose
    A's original cleanup and verified pre-entry revocation, and let the real
    settle_revocation path release its claim. Keep the negative control where
    disposition remains unresolved after cleanup and ownership stays held.
[ ] Begin with two owners, capacity one or two, and short operation identities.
    Proposed default: at most 32 examples with 40 rule steps each. Record the
    actual generated/executed counts; the product is not a coverage claim.
    Proposed extended profile: 1,000 examples with 150 steps and two to four
    owners. These bounds are unrun and must be revised from measured cost.
    Capacity one proves release-before-resumption; capacity two or more proves
    independent sibling progress while another claim remains held. The shared
    registry is not lane-keyed; lane/resource readiness is a separate condition.
[ ] Maintain an independent ledger of grants, original operation identities,
    accepted handles, scientific dispatches, terminal decisions and exact
    report bytes. Check safety after every command, not just a final trace.
    State fields from the implementation cannot be the whole expected model.
[ ] Enforce owner isolation; retirement evidence before required replacement;
    no new scientific effect after permission expires or is revoked; retained
    accepted preparation/outcome after later cleanup failure; no science
    replay as a cleanup strategy; one logical terminal decision; and no late
    retired owner mutating its successor. Identical transport retries remain
    permitted. Explicit input correction and provider-authorized scientific
    retries are separate protocol transitions, not automatically violations.
    Map these checks to S1-S8 and I2; an independent enabled operation's progress
    is I1. Keep L1-L3 checks conditional on the stated evidence and scheduling.
[ ] Add conditional progress rules: when required external gates complete,
    permission/disposition resolves and scheduling is allowed, the original
    owner can settle, eligible work can use released capacity, and stop can
    finish its required retirement/handoff duties. A forever-unknown child
    exit has a safety assertion, not an unconditional liveness obligation.
[ ] Use gates for ordering. If generating deadline advancement, use an isolated
    test clock/loop that actually services the timers used by the composition;
    validate the clock seam against existing real-timer witnesses. Do not
    globally replace sleep/time or turn watchdog expiry into retirement proof.
    Until that seam is established, label generated ordering coverage and real
    deadline coverage separately. No broad runtime clock refactor is required.
[ ] Keep an independent wall-clock watchdog for stuck harnesses. A real
    deadline crossed under starvation must still revoke new-work permission;
    the harness cannot require that work succeed regardless of scheduling.
[ ] Emit the minimized command history, immutable identities, failure boundary,
    Hypothesis version, profile and reproduction information. Replay the
    recorded commands against fresh owners, and retain a minimal deterministic
    regression for each fixed defect. Seed alone is insufficient across
    changed library versions. Drain retained fixture work after the verdict.

Exit after milestone 4 supplies the test environment: a test-only ownership
perturbation yields a useful shrunk witness; replaying it fails at the same
behavioral boundary. The composed owners in the qualified candidate satisfy
the selected corpus without unexplained tasks or asyncio errors. A real defect
gets an owning fix; never weaken runtime semantics to accommodate the harness.

5. Extend the small actual-process layer, then apply bounded contention
----------------------------------------------------------------------
[ ] Extend the existing B3/child/reply-boundary tests rather than creating a
    second process harness. Gate creation after the original launch succeeds,
    communication, original wait/exit observation and cleanup observers.
    Preserve the actual child/PID and the original waiter throughout.
[ ] Cover cancellation during launch; communication timeout/partial reply;
    interrupted cleanup; signal escalation; exit observation after its first
    allowance; repeated retirement; and a cancelled observer joining the same
    cleanup. State which edges existing witnesses already cover before adding.
[ ] Add only the missing simultaneous-owner/process ordering that the composed
    model exposes. One owner remains held while another completes its original
    operation and handoff. Releasing the late original exit cannot mutate the
    successor or renew an expired permission or cleanup allowance.
[ ] Distinguish simulated delayed evidence from physical survival. Withholding
    child.wait() after the process has died tests uncertain retirement; it
    does not exercise an unkillable operating-system process. EOF and a sent
    signal are not positive exit evidence. Retain original failures separately.
[ ] Proposed initial repeat cap: ten normal runs and three runs with bounded,
    owned external CPU contenders for the focused causal witnesses. These
    counts and loads are unrun, optional stress qualification, not new default
    suite requirements. Fix the contender budget and stop/join it on all exits.
    Declare the CPU quota/load and never block the event loop to manufacture
    starvation. Keep normal semantic deadlines observable under that load.
    Record actual load, timing budgets and missed watchdogs; do not widen time
    allowances until a race passes or assert unconditional success under load.
[ ] Assert causal order and forbidden effects under contention. Use real
    deadlines for behavior that depends on real scheduling. Progress claims
    require the declared scheduling/resource assumptions; a delayed process
    observation must never be silently converted into confirmed retirement.

Exit: process evidence names original PID/operation and observed retirement,
with no leaked child or unexplained asynchronous error. The scope is local
fault injection; deployment, power-loss durability and live science are separate.

10. Evidence, release and cutover gates
--------------------------------------
[ ] For a discovered defect, preserve a minimal behavioral red and an adjacent
    owning fix with exact artifacts. Correct behavior needs a passing guard,
    not an invented red. A missing proposed API is not a lifecycle failure.
[ ] Requalify changed artifact bytes against applicable SDK and consumer gates.
    Update dependency pins only to the artifact those receipts identify. Preserve
    longer-campaign seeds/traces and measured costs without claiming exhaustiveness.
[ ] Before an authorized cutover, stop old admission and settle required duties
    or verify durable transfer to a surviving owner. Preserve delivery bindings
    and queued rows. Keep an old process alive if it alone owns unfinished work;
    a drain timeout or an in-memory note is not custody transfer. Apply the same
    obligation check to rollback. Never compare with simultaneous live schedulers.
[ ] Publish only what the evidence establishes: bounded generated schedules,
    local process faults, installed consumer composition, native topology and
    live scientific execution are separate qualification levels. Historical
    note 061 reconstructions and note 058 counts do not qualify new source trees.

Completion: the default SDK suite owns a small shrinking composed campaign;
the process layer proves real ownership at its OS/IPC boundary; consumers keep
thin installed-composition proofs and their scientific/native contracts. The
later extraction has one shared service owner without a second runtime registry,
replacement protocol, publisher or general-purpose fuzz framework.
