# provider-core 0.6.19

The published acquisition owner can project several ordered UID and GID values
from one identity observation, including mixed forward and inverse mappings.
Generalized callers supply the exact image, interpreter, probe user and resource
ceilings, and can select the user namespace. The existing acquisition host-owner
interface is preserved.

Shell consumers use `acquisition_project_ids` to keep the Python probe and its
native client under the existing cooperative process owner. A positive retirement
receipt records that both owners have settled. Caller values change only after
final success, complete canonical output and that retirement proof; receipt alone
does not authorize filesystem grants. Cancellation retains its original status,
and unresolved retirement retains diagnostics and blocks further scope work.

The bundle pins linux-idmap 0.3.4. Its CLI rejects late cancellation during output
publication or signal-handler restoration, even when stdout already contains
plausible mappings. Consumers must check the final exit status before using them.

Providers obtain the new shared owner through their maintained verified-source
refresh command using this release's pinned acquisition archive. Replacing an
existing snapshot first verifies it against its recorded release. Provider host
adapters must adopt the published entry point rather than copy the probe or
process-supervision implementation.
