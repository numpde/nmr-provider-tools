# provider-core 0.7.6

2026-11-24. Protected failure diagnostics now retain bounded exception notes across native worker calls, alongside causes and remote frames. Notes remain diagnostic evidence: they do not change failure classification or retry eligibility. Arbitrary custom exception attributes are not transported.

The wire admits at most eight notes per exception, 2,048 characters per note and 32,768 note characters across the causal graph. Oversized notes are omitted whole, with an explicit omission marker. Received notes remain separate from ordinary exception tracebacks and are exposed through the redacted diagnostic renderer. Worker and caller must use the same SDK version because the private error envelope has changed.

`JobService` accepts `diagnostic_secrets` for redacting configured credentials from shutdown failure reports. Attempt draining preserves causal evidence and independent cleanup or reporting failures; native host exit receipts are logged before the service reports the unavailable host. Codec rejection diagnostics retain their code and safe message, and Unicode decode failures retain encoding, position and reason without the original input bytes. Providers still own redaction of scientific input and any additional secrets before publishing their diagnostic evidence; this is not a blanket privacy guarantee for arbitrary exception prose.

Five provider-independent integration tests exercise the installed SDK with real worker processes, the interpreter and Attempt lifecycle: interpretation failure before science, failure after partial scientific completion without replay, independent cleanup failure, diagnostic reporting failure, and eligible retry in a fresh worker. They check causal evidence, bounded notes, correlation and credential/input redaction. ChefNMR2 separately verifies its adapter's model-failure handoff to protected Attempt evidence and logs; its model is simulated. No live scientific accuracy or deployment claim is made. Repository convention findings remain recorded in `notes/092_repo_checks_status.html`.
