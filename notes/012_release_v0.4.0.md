# provider-core 0.4.0

This release removes the producer disk-checkpoint and stopped-recovery APIs. It is a breaking upgrade from 0.3.0. Shared delivery continues to retain exact pending results durably and publish them independently of scientific workers.

Replace `CheckpointStore`, `AttemptRecovery` and store-taking lifecycle constructors with the live interfaces. Share one `AttemptClaims.live()` registry across the supervising process and use `AttemptController.live()`, or integrate the separate `AttemptStarter.live()` and `AttemptExecutor.live()` helpers under your own qualified lifecycle owner. Providers can continue to use `DeliveryClient` directly without adopting the shared execution controller. Scientific preparation, inference, model runners, offerings and model configuration remain provider-owned.

Before upgrading a provider, stop admitting new work and let its existing supervisor settle its work, worker cleanup and reporting duties. Retain unresolved owners and reports until reconciled. Preserve the existing shared delivery queue and provider lifetime root. The new SDK does not read producer checkpoint files or reconstruct Attempts after restart; old records do not authorize another calculation.

Live bookkeeping lasts only as long as its supervisor. Reports acknowledged by shared delivery continue independently. If the supervisor dies before handover is confirmed, a report may already be queued or may be lost; restart does not infer its disposition or fabricate a failure. Use `shutdown_ready`, together with the provider's other resource owners, before ending an orderly supervisor lifetime. `work_settled` alone does not establish that reporting duties are complete.

Runner retirement messages must now include an explicit supported reason. Missing or unknown reasons are rejected. Keep the SDK runner and its reader on the same qualified protocol version. An observed original worker exit can establish crash evidence only while the current Attempt and phase permit reporting; timeouts, EOF and deliberate interruption do not establish an unexpected crash.

The upgrade also requires complete inputs when constructing lifecycle owners and restores the intended validation refusal for an acknowledgement belonging to another Job, provider or analysis kind. Retained outcomes, exact report bytes and independent cleanup failures remain available to their live owners. Delivery acknowledgements still establish durable local enqueue, not API acceptance.

Qualification covers installed-package unit, contract and integration tests, offline deployment rendering and proxy tests, and repository process, signal and container-boundary tests. The drain-status classification test now waits long enough for the helper's declared startup and native-work budgets; production deadlines are unchanged. These checks do not establish numerical accuracy, GPU behavior or migration of a running provider. Each provider must qualify its own integration before cutover.

Python 3.12 or newer is required. Runtime and build dependency versions are unchanged from 0.3.0. Distribution remains through GitHub Releases. The release includes the wheel, source distribution, complete hash installation lock, source record, artifact hash manifest and build/test logs. Earlier published assets remain unchanged.
