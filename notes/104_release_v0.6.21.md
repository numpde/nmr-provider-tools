# provider-core 0.6.21

`ProcessExecutionHost.observe_exit(wait_seconds=...)` observes the original scientific worker while its allocation is idle or serving, without starting retirement or spending its cleanup allowance. Concurrent waiters share one retained monitor; cancelling or timing out a wait leaves that owner intact. The supervisor reports confirmed exit before scratch cleanup. The returned evidence is the same identity-correlated record retained by `RunnerSession.original_exit`. It does not authorize releasing resources or determine an active Attempt's scientific outcome. Providers retain responsibility for withdrawing the affected offering and publishing their corrected inventory.

Retirement records deliberate shutdown before scientific cleanup can exit the child. An exit learned after interruption cannot establish its original cause. Control loss and lifecycle frame failure remain distinct from confirmed worker exit; only caller wait expiry is reported as `TimeoutError` by the exit observer. New analyses and invocations are refused locally after known worker loss, while exact resubmission still returns its retained original operation. Cleanup joins the original monitor and confirms native retirement separately.

Native startup retains the caller's absolute `startup_not_after` deadline across deferred connection and admission. It does not cap later model initialization or healthy residence. Unrelated executables no longer inherit the scientific worker's lifetime lease. `failure_evidence_json` applies one encoded-byte budget to the complete failure record, preserving causal relationships and required outcome facts while bounding diagnostic text. These SDK guarantees replace consumer timing, descriptor and diagnostic workarounds; real-provider integration and GPU qualification remain separate work.

In-process analysis acquisition now requires exact allocation handles through `open_analysis(allocations=frozenset(...))`; the legacy public analysis-ID and allocation-name form has been removed. Shared identity, binding-revision, loop-affinity and cleanup-state checks now have one implementation. The unwired legacy delivery reassociation method has been removed; persisted legacy rows remain held for inspection or explicit discard. Error messages throughout SDK, build, acquisition and deployment code now show failed relationships and relevant evidence more directly.

Use the same identified SDK in the parent and scientific runner; the lifecycle stream now includes an exit notification before its final cleanup receipt. The release includes the wheel, source distribution, complete and native installation locks, wheelhouse bundle, acquisition-owner archive, source record and hash manifest. Attached build and qualification logs identify the exact bytes tested, executed suites and privacy skips. Formatting, naming and diagnostic-style inventory findings remain deferred; installed behavior, native ownership and cleanup, and artifact integrity remain release gates.
