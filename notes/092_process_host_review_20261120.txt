## Boundaries and resulting behavior

### Declaration and receiver

The class-only HostedContribution compiles declarations and selects call
bindings without a parent scientific receiver. Exact-object adoption remains
supported. submit_method requires a real bound receiver; an absent receiver
cannot match an unbound function merely because both expose None.

Contribution constructors remain lightweight. Acquire resources in initialize,
after the SDK resident owns the object, retaining partial acquisitions on that
object for close. A factory returning a wrong or already owned object is refused;
the SDK cannot recover resources secretly acquired inside a failing constructor.

Offering identity, selected metadata/bindings, prompt-reading timing and the
receiver -> analysis -> interpreter cleanup order remain as established by the
preparation checkpoint. Request workflows contain no process launch or model
lookup logic.

### Submission and observation

Local framing and supported byte-policy checks precede transmission. The parent
then retains the operation before sending. Only a validated NotAdmitted reply
removes it. Lost or malformed acknowledgement retains the original identity and
quarantines uncertain communication; repeating submit returns that owner.

One serialized scientific channel has a deadline across queue acquisition, send,
header and body. Original communication tasks remain owned when a caller stops
waiting. The original observation task publishes its reply on the event loop;
an abandoned waiter cannot discard it or overwrite a newer final observation.
Channel failure preserves known scientific facts and adds infrastructure evidence.

The first profile permits at most 1 MiB per encoded input/result payload inside
an 8 MiB frame. Larger requested per-operation allowances are refused before
transmission. Exception causes, contexts, groups and text are bounded. Known SDK
semantics come from actual exception types; coincidental foreign class names do
not grant scientific rejection or start-deadline semantics. Bad reply encoding
produces bounded infrastructure evidence without repeating the command. Other
oversized records remain a transport failure, not a chunk-transfer capability.

### Cleanup and terminal evidence

Calling close or release_result starts and retains cleanup immediately.
Observers only wait for that owner. Transport failure does not invent an expired
cleanup allowance. An invalid result reference cannot poison the valid result's
release control.

Analysis opening is explicit. Submission cannot implicitly recreate a closed
analysis, and unknown close cannot invent success. Parent-generated fresh UUIDs
remain the identity rule for this private, same-installation channel.

Close captures and joins earlier owned reads, observations and releases. New
ones wait for the original cleanup. After successful scientific close, the
parent reads final observations individually, stores them on the original
handles, and sends forget_analysis once. Only its acknowledgement releases the
parent analysis slot. Uncertain acknowledgement is not retried.

The child then drops records without available results. Available results remain
independently owned until release. Release similarly drains earlier reads and
publishes its final observation before dropping the worker record. This replaces
the arbitrary 128-entry history and avoids an unbounded aggregate close reply.

### Native process control

ProcessExecutionHost now takes a fresh RunnerSession supplied by deployment.
It does not launch another supervisor. Deployment starts the existing runner
with owner-session lifetime and a fixed installed command:

    python -I -B -m provider_core.process_worker

The runner adds its science FD, inherited lifetime lease and native operation
identity. The worker retains the lease through process exit, including executor
thread finalization. The parent retains AsyncRunnerSession before connecting.
The runner owns native stop, reaping and private scratch cleanup independently
of the scientific communication socket.

Deployment owns the runner endpoint, role, stable lock identity, native budgets
and restricted launch environment. The supervisor environment must contain only
what this scientific worker needs; session injection does not itself filter a
misconfigured supervisor's environment. Existing runner FD restrictions remain.
Do not infer descendant containment from direct-worker supervision.

NMRPeak process mode requires process_session at provider startup and one
configured offering. Thread mode stays the default and refuses an unused process
session. Process checkpoint paths are resolved before the child enters its
private working directory. Configuration refusals before host construction leave
the supplied, unconnected session with its caller; the constructed host owns it.

Retirement gives startup, outstanding scientific handoffs and contribution close
one scientific grace interval. Expiry does not cancel the original action. Native
observation/stop/join uses the runner session's separate original aggregate
allowance. After a successful scientific-close reply, half that native allowance
is reserved for stop/join if interpreter exit stalls; no reader or budget restarts.
Deployment must leave sufficient native allowance for its configured supervisor
TERM, KILL, reap and scratch-cleanup bounds.

Original setup and communication are joined before their descriptors close.
Terminal non-acquisition is assessed after setup joins. A later native setup
failure is retained unless it is the exact cause already reported by start.

The scientific cleanup observation and native retirement receipt are distinct.
Confirmed worker exit and scratch release can settle native resources while
scientific cleanup failures remain reported. Such historical diagnostics do not
keep a dead allocation charged. Unconfirmed worker or scratch ownership remains
unsettled and unavailable. There is no automatic restart, replay or replacement.
